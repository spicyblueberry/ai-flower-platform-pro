# 花材图片命名规范

## 一、命名格式

图片统一使用以下格式：

```text
<花种码>_<颜色码>.<原扩展名>
```

例如：

```text
37_2.png
65_1.png
83_4.png
88_11.png
```

分别表示：

| 文件名 | 花材库花种 | 颜色 |
| --- | --- | --- |
| `37_2.png` | 37 蝴蝶兰 | 粉色 |
| `65_1.png` | 65 秋色绣球 | 铁锈红 |
| `83_4.png` | 83 剑叶 | 黄绿条纹 |
| `88_11.png` | 88 芦苇 | 棕褐色 |

## 二、花种码

花种码直接使用花材库中的 `id` 字段：

```text
knowledge_base/flower_knowledge.json
```

例如花材库中：

```json
{
  "id": 37,
  "name": "蝴蝶兰",
  "color": "粉色、白色、紫色"
}
```

则这三张图片分别命名为：

```text
37_2.png
37_3.png
37_6.png
```

花材库中的 ID 存在不连续情况，例如没有 `28`、`57`。文件中出现跳跃编号属于正常现象，不应自行补号。

## 三、颜色码

当前项目统一使用以下颜色码：

| 颜色码 | 含义 | 常见颜色描述 |
| --- | --- | --- |
| `1` | 红色 | 红色、玫红、深红、铁锈红、红色枝干 |
| `2` | 粉色 | 粉色、浅粉、桃粉 |
| `3` | 白色 | 白色、米白色、乳白色 |
| `4` | 黄色 | 黄色、金黄色、黄绿色、黄绿条纹 |
| `5` | 香槟色 | 香槟色、香槟金 |
| `6` | 紫色 | 紫色、紫红、蓝紫色 |
| `7` | 蓝色 | 蓝色、灰蓝色 |
| `8` | 绿色 | 绿色、深绿色、油绿色、灰绿色、复古绿 |
| `9` | 橙色 | 橙色、橙红色、以橙色为主的组合色 |
| `10` | 多色 | 多色、吸染多色、明显混合配色 |
| `11` | 褐色 | 褐色、棕褐色、棕色 |

### 复合颜色的处理

一张图片只使用一个主要颜色码，不因为画面包含多个颜色而重复命名。

常用判断方式如下：

| 花材库描述 | 文件名颜色码 | 示例 |
| --- | --- | --- |
| 白色黄心 | `3`，以白色花瓣为主 | `19_3.png` |
| 金黄花瓣、深褐花心 | `4`，以金黄色花瓣为主 | `31_4.png` |
| 黄色带褐斑 | `4`，以黄色为主 | `36_4.png` |
| 橙蓝相间 | `9`，以橙色为主 | `39_9.png` |
| 复古绿 | `8` | `65_8.png` |
| 铁锈红 | `1` | `65_1.png` |
| 灰蓝 | `7` | `65_7.png` |
| 黄绿条纹 | `4`，以黄色条纹为识别色 | `83_4.png` |
| 棕褐色 | `11` | `88_11.png` |

## 四、同花同色的重复图片

同一花种、同一颜色存在多张图片时，在基础名称后追加两位序号：

```text
<花种码>_<颜色码>_2.<扩展名>
<花种码>_<颜色码>_3.<扩展名>
```

其中 `_2`、`_3` 表示同一花材颜色的第 2、第 3 个版本。

例如：

```text
12_3.png
12_3_2.png
```

当前目录中 `12_3_2.png` 已纠正为洋甘菊、并改为 `19_3.png`，因此现在没有该重复版本。以后新增重复图片时仍按此规则处理，禁止直接覆盖已有文件。

## 五、重命名流程

1. 从 `knowledge_base/flower_knowledge.json` 读取花种 `id`、中文名和颜色列表。
2. 读取 JSON 时使用 UTF-8，避免中文显示为乱码。
3. 逐张查看图片，先判断花种，再判断主要颜色。
4. 按“花种码_颜色码”生成目标名称，扩展名保持不变。
5. 检查目标文件是否已存在；存在时先确认是否为同花同色版本。
6. 同花同色重复图片追加 `_2`、`_3`。
7. 检查是否存在两个源文件映射到同一个目标名称。
8. 使用移动或重命名操作，不复制、不覆盖。
9. 重命名后重新检查文件名、花种 ID、颜色码和图片可读性。

## 六、交接校验清单

完成后应满足以下条件：

- 所有图片名符合 `<花种码>_<颜色码>.<扩展名>` 或 `<花种码>_<颜色码>_版本号.<扩展名>`。
- 每个花种码都能在 `flower_knowledge.json` 中找到。
- 每个颜色码与花材库颜色描述相符。
- 同一完整文件名只出现一次。
- 没有花材图片生成需求一类临时文件名残留。
- 所有 PNG/JPEG 文件都能正常打开。
- 图片视觉内容中的花种、主色与文件名一致。
